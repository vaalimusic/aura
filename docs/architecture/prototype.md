# Desktop prototype · этап I

Документ описывает сохранённый демо-режим первого этапа (`--demo` / «Демо UI»). Текущий рабочий режим использует реальный движок: см. [Audio P2P](audio-p2p.md).

## Границы

`aura-core` содержит демонстрационные данные, состояние и семантические команды. Не читает устройства, сеть или файловую систему. Не создаёт поддельную криптографическую идентичность и не выдаёт mock-соединение за реальное.

`aura-ui` превращает состояние в EvertyUI PaintList и интерактивные области в логических координатах. Представление одинаково для нативного окна и PNG-превью.

`aura-desktop` владеет winit event loop, softbuffer surface, DPI-преобразованием, вводом и платформенным треем. Команды мыши, клавиатуры и трея идут в одно ядро. При сбое создания трея окно закрывает процесс, чтобы не оставлять недоступное приложение.

## Состояния

Первый запуск: эфир выключен, источник не выбран, Smart Feed на паузе. Выбор источника сам по себе не включает эфир. Смена источника или аудитории останавливает текущий демоэфир.

Smart Feed выбирает только активные, не исключённые источники. Переход идёт по порядку с возвратом в начало. Завершение текущего источника снимает закрепление и выбирает следующий; без кандидатов — ожидание. Кнопка симуляции завершения находится в настройках. Автоматическое определение тишины и резервное соединение относятся к следующим этапам.

Скрытие окна оставляет процесс и трей доступными. В скрытом/occluded состоянии приложение не ставит таймеры анимации. В видимом окне визуализация обновляется примерно 12 раз в секунду; в паузе event loop ожидает ввод. Это начальный режим, не измеренная гарантия потребления ресурсов.

## Следующие границы

По мере реализации выделять `aura-audio`, `aura-network`, `aura-identity`, `aura-social`, `aura-feed` и `aura-protocol`. Не создавать пустые заглушки сервисов, которые выглядят работоспособными. Реальные события движка должны обновлять модель через команды/сообщения, не блокируя UI.

До этапа II не выполняются системный захват, кодирование, вывод аудио, поиск процессов, P2P, выдача приглашений и сохранение профиля. Windows — первая платформа проверки; сборка и native dependencies на Linux/macOS ещё требуют отдельной проверки.
