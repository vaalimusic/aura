# Configured Community Nodes

The desktop supports one to four explicitly configured, PeerId-pinned TCP relays. Configuration precedence is `AURA_RELAYS` (semicolon-separated), legacy `AURA_RELAY`, then `<profile>/nodes.txt` (one address per line, `#` comments). On first use the profile file contains `aura.ltwo.ru` and the independently hosted `aura2.ltwo.ru`. The exact single-node file generated by the previous version is upgraded atomically; custom files remain untouched. Configuration reads are bounded to 8 KiB. Invalid or unpinned routes are rejected; addresses received from unknown peers are not added automatically. Each independent node has its own identity.

The stable social swarm reserves presence on every configured node. Each reservation reconnects independently with a 16-second retry interval. Losing one node does not clear authenticated friend presence while another reservation remains available. Friend dialing uses all configured relay routes; polling, consent, expiry and job/rate limits remain in force. Two clients need at least one common reachable configured relay to find each other. The UI displays the number of ready reservations when multiple nodes are configured.

When a broadcast starts, its separate audio identity tries configured nodes in order. Capture starts only after a reservation succeeds. Cancellation prevents moving to another node or starting capture. The audio swarm then reserves the same broadcast identity and capability on the remaining configured nodes, retrying failed reservations every eight seconds. Audio is still sent only to connected listeners; reserving a backup does not upload a second audio feed. The invitation stays unchanged and remains readable by existing `aura://v2/` readers.

The desktop listener first uses the invitation's explicit route. On transport failure it cycles through routes derived only from its locally configured, PeerId-pinned nodes, keeping the invitation's original broadcaster PeerId and capability. Every route still establishes end-to-end Noise to that same broadcaster; no alternate publisher or new authorization is accepted. Invalid audio authentication or framing fails immediately. Transient transport errors retry with a 750 ms minimum delay for roughly a minute (plus the final bounded connection attempt). Cancellation interrupts connection, backoff and streaming. The legacy single-route receive API remains available for diagnostics.

An active relay circuit can break on node failure, causing a short playback gap; the original capture and playback workers survive and the listener reconnects to a reserved backup. If every node goes offline, capture continues consuming fresh bounded frames while reservations retry; a listener can recover when a common configured node returns within its retry window. After the window expires the ordinary ended/Smart Feed behavior applies. There is no gapless delivery guarantee. The UI indicates recovery, suspending Smart Feed pause/silence decisions until reconnection or final failure. Old clients can read the same invitation but need an updated receiver for automatic failover. Both peers need a common configured, reachable node.

An intentional Stop sends a zero-length audio end marker and waits briefly for its acknowledgement before closing the swarm. Updated receivers treat this as terminal, so Smart Feed can move on immediately. Older receivers reject the marker as a terminal invalid frame, preserving their previous end behavior. Invalid capabilities receive an explicit rejection and are not retried. Abrupt process termination remains a transport failure and can use the recovery window.

Automatic discovery of additional community nodes, validated DHT records and direct-route upgrade remain pending. The shipped defaults contain two nodes on independent VPS hosts; tests of two containers on one host alone would not establish that redundancy.

`deploy/compose.yaml` runs an additional node with a persistent identity volume, unprivileged user, read-only root filesystem and CPU/memory/process/file limits. A second host needs its own public advertise address and reachable TCP port. Read its public PeerId with `--identity`, then add the full multiaddr on both desktops. Keep the private identity key on its host.

Local integration tests stop the primary relay, join a new client using only the backup, restore the original relay with the same identity, and verify reservation recovery. Audio tests verify startup fallback, cancellation, uninterrupted worker lifetime across primary failure, resumed frame delivery and metadata after both nodes go offline and one returns. Invalid capabilities fail without retry. All test identities and contact stores are isolated; these checks do not replace a two-PC test with real Windows audio.
