# Windows now playing

The desktop observes Windows GSMTC on a dedicated MTA thread, without controlling a player or analysing captured sound. It starts only for an explicitly selected broadcast source. Manager/session event subscriptions are removed on replacement and shutdown. Windows async reads have three-second deadlines; metadata errors fall back to an empty snapshot and do not stop audio. Transient manager failures retry while the broadcast remains active.

Binding never uses the system current session. The selected PID, executable and process start time must still match. Same-executable child processes are grouped as in capture; multiple root instances disable matching. The source process's Win32 ApplicationUserModelId, when available, or the executable stem must identify exactly one GSMTC session. Browser session IDs such as `Chrome` and `MSEdge` match `chrome.exe` and `msedge.exe`; window titles, track strings and the most recently active player are not guessed. This intentionally leaves some compatible applications without metadata when a trustworthy association is unavailable. GSMTC identifies applications, not audio endpoints or individual browser tabs.

MediaPropertiesChanged refreshes title/artist/album and the thumbnail; PlaybackInfoChanged and TimelinePropertiesChanged refresh playback/timeline. SessionsChanged rebuilds the binding. A three-second source/session check handles process changes; a thirty-second fallback refresh covers missed property notifications. The timeline is read about once a second. Playing position is advanced from LastUpdatedTime and playback rate only for a recent timestamp, bounded by the reported duration. Paused/stopped positions remain fixed.

Local thumbnails are limited to 1 MiB and 4096 pixels per dimension before decoding, then cropped and encoded as 160×160 JPEG (up to 24 KiB). No remote artwork URL is followed. No metadata or cover is written to the user's profile or an image cache.

`aura-media` validates versioned JSON messages: text length/control characters, bounded timeline, 48 KiB message, and JPEG dimensions/decoded allocation. A per-connection cover state sends a JPEG on the first snapshot and on a change, Keep on subsequent timeline messages, and Clear on removal. A late listener receives its own full first cover. Receivers clear metadata on stream failure; a ten-message-per-second limit bounds unsolicited update traffic.

Relay uses a separate `/aura/metadata/1` stream on the audio connection. It authenticates the current broadcast's 256-bit capability over Noise independently of the audio stream. It has separate tasks/deadlines/listener limits so a slow cover consumer cannot block Opus. Direct QUIC sends metadata on the already authorized reliable bidirectional stream; audio remains in QUIC datagrams. Old peers can continue to exchange audio without understanding metadata. The server requires no update or additional port.

The player displays title, artist, album, application, playback state, timeline and artwork. The current title and artist can be copied from the card or with `Ctrl+Shift+C`. Empty/ambiguous sessions use a neutral player card. Stop, source change and session generations prevent late events from repopulating a new session's track. Pause is informational: it does not yet switch Smart Feed or remotely control another application's playback.

Tests cover ambiguous matching, bounded image/message decoding, first/change/Keep/Clear cover semantics, independent QUIC/relay metadata updates, and renderer clipping/alpha/DPI. `--media-info <source PID>` inspects one currently listed capture source; `--media-watch <PID>` observes its events for fifteen seconds without capturing or publishing sound. The manual `--mesh-smoke` sends synthetic metadata and artwork through the configured relay, changes track/state, and verifies the independent synthetic audio pipeline with muted output.

Reference API: [Microsoft GSMTC session](https://learn.microsoft.com/en-us/uwp/api/windows.media.control.globalsystemmediatransportcontrolssession).
