# Aura

**The music between us.**

Компактное настольное социальное радио на Rust и EvertyUI. Работают реальный Windows-аудиотракт, прямой QUIC, зашифрованный relay через Aura Node и сохранённые друзья с присутствием и подключением к эфиру. Постоянный Ed25519 Aura ID хранится локально (DPAPI в Windows).

## Запуск

Нужны Rust stable (1.89+), CMake и MSVC Build Tools с Windows SDK. Opus собирается из исходников и статически включается в приложение. Process Loopback требует Windows build 20348+. При ошибке захвата Aura не переключается на общий системный микс.

```powershell
cargo run -p aura-desktop
```

Релизная сборка:

```powershell
cargo build --release -p aura-desktop
```

Исполняемый файл Windows: `target/release/aura-desktop.exe`.

## Реальный эфир: два компьютера

По умолчанию выбран режим **«Через Aura Node»**: оба клиента подключаются исходящим TCP-соединением к `aura.ltwo.ru:45071`, домашний проброс портов не нужен. На обоих ПК должна быть новая сборка с поддержкой `aura://v2/`.

1. На компьютере вещателя запустите музыку. В Aura нажмите «Обновить», выберите приложение, затем «В эфир».
2. Захватывается выбранный процесс **и его дочерние процессы**. Для браузера это может включать несколько вкладок. PID и дерево процесса указаны в окне.
3. Нажмите «Копировать приглашение», передайте ссылку другу доверенным способом.
4. На втором компьютере скопируйте ссылку целиком и нажмите «Вставить приглашение и слушать».
5. «Остановить» прекращает сессию и отзывает приглашение. Следующий эфир получает новые ключи и разрешение. Смена источника также останавливает сессию.

При запуске захват и воспроизведение выключены; в рабочем режиме подключается служба присутствия. Работает одна аудиосессия на экземпляр: вещание или приём; до четырёх слушателей на эфир. Приглашение — временный bearer-доступ: слушать может любой обладатель ссылки. Кнопка «Мой Aura ID» копирует публичный PeerId, не приватный ключ. Профиль Windows: `%LOCALAPPDATA%/Aura/identity.key`; он защищён DPAPI текущего пользователя.

## Друзья по Aura ID

1. Установите сборку с друзьями на обоих ПК. Откройте вкладку «Друзья», при желании измените своё имя.
2. Друг копирует «Мой Aura ID» и передаёт вам один раз. Нажмите «+ Aura ID», вставьте идентификатор и сохраните.
3. При работающих клиентах друг увидит входящий запрос и нажмёт «Принять». Встречные запросы также подтверждают дружбу.
4. Когда друг включит эфир **через Aura Node**, появятся статус «В эфире» и кнопка «Слушать». Новую ссылку передавать не требуется: кнопка каждый раз запрашивает приглашение текущего эфира у проверенного Aura ID.

Запросы и подтверждения хранятся локально в `friends.json` рядом с ключом и переживают перезапуск. Имя по умолчанию — «Слушатель». Присутствие обновляется примерно раз в 4 секунды; исчезновение друга из сети определяется примерно за 13–17 секунд. Если адресат выключен, запрос ждёт его следующего подключения; сервер очереди запросов не хранит. В демо служба присутствия отключена. Повторный запуск одного профиля блокируется; для независимых тестовых экземпляров используйте разные `AURA_PROFILE_DIR`.

Обмен `/aura/social/1` идёт по Noise с проверкой постоянного PeerId. Доступ к эфиру передаётся только подтверждённым контактам. Аудиосессия имеет отдельный временный PeerId; его приглашение приходит через постоянный канал друга. Приглашения и статусы не записываются в базу контактов. Удаление/отклонение оставляет локальную блокировку повторных запросов; явное добавление того же ID снимает её. При удалении контакта во время собственного эфира весь эфир останавливается для отзыва уже выданных ссылок; затем его можно включить заново. Ручная пересылка ссылки остаётся отдельным способом выдачи доступа.

Это discovery по уже известным Aura ID через выбранный relay. Публичного каталога и синхронизации контактов между устройствами пока нет. Smart Feed перебирает активные эфиры принятых друзей. Прямые UDP-эфиры пока открываются вручную по ссылке. Пилотный VPS ограничен 16 одновременными circuits, включая каналы присутствия; большие списки друзей ещё не проходили нагрузочные испытания.

Для старого **прямого режима** нажмите переключатель маршрута в карточке плеера, пока сессия остановлена. В этом режиме вещатель слушает **UDP 45070**, адрес для приглашения выбирается по сетевому маршруту ОС. Через Интернет нужны внешний адрес и доступный UDP-порт/проброс. При CGNAT или закрытом UDP выбирайте Aura Node. Автоматического переключения между маршрутами пока нет. Firewall и маршрутизатор приложение не перенастраивает. Старые ссылки `aura://v1/` принимаются автоматически в прямом режиме.

Для прямого режима при нескольких интерфейсах/ручном пробросе задайте адрес перед запуском:

```powershell
$env:AURA_BIND = '0.0.0.0:45070'
$env:AURA_ADVERTISE = '192.168.1.10:45070' # Замените адресом, доступным другу
./target/release/aura-desktop.exe
```

Тракт: Process Loopback → 48 кГц stereo → Opus 128 кбит/с, 20 мс → транспорт → jitter buffer → WASAPI. Приватный прямой транспорт — QUIC/TLS 1.3 с проверкой сертификата из ссылки. Приватный relay — libp2p Circuit Relay v2 со сквозным Noise между клиентами и проверкой PeerId вещателя из ссылки; VPS не может расшифровать этот поток. В обоих приватных случаях вещатель проверяет случайный 256-битный токен до отправки медиа. Публичный режим `/aura/public/2` передаёт один поток на узел, который раздаёт его слушателям без перекодирования: соединения с узлом шифруются Noise, но сам узел имеет доступ к аудио. Аудио на диск не сохраняется.

Узел на `aura.ltwo.ru` работает как ограниченный пилотный relay/bootstrap: до 32 резерваций и 16 circuits; circuit ограничен двумя часами / 256 МиБ. Лимит может завершить длительную сессию; автоматическое переподключение ещё не реализовано. [Развёртывание и эксплуатация узла](deploy/README.md).

Громкость управляет реальным выводом, визуализация использует RMS PCM. RTT — сетевой round trip, буфер — длительность jitter-очереди; это не end-to-end задержка. «Потери» — сумма локальных отбрасываний и PLC, а не процент потерь канала.

Закрытие окна скрывает приложение в Windows-трей. «Завершить Aura» останавливает звук и соединение. При недоступном трее закрытие завершает приложение. Скрытое окно не запрашивает кадры анимации. Linux/macOS audio backend и трей пока не реализованы.

## Название трека и обложка

Во время собственного эфира Aura читает GSMTC выбранного приложения Windows: название, исполнителя, альбом, обложку, Playing/Paused/Stopped и доступную позицию. Название и обложка обновляются по событиям плеера; Spotify API и авторизация Spotify не требуются. У слушателя сведения приходят отдельным зашифрованным каналом, независимо от Opus, и показываются в карточке плеера. Это работает через Aura Node и в прямом режиме; для отображения метаданных обновите оба клиента.

Сопоставление использует PID/время запуска и единственный корневой процесс; для Chrome и Edge имя GSMTC (`Chrome`, `MSEdge`) сопоставляется с exe (`chrome.exe`, `msedge.exe`). При нескольких сессиях или экземплярах приложения остаётся нейтральная карточка. Текущая системная медиасессия не подставляется. Кнопка «Копировать» и сочетание Ctrl+Shift+C копируют название и исполнителя.

Обложка уменьшается до 160×160 и передаётся при смене. Метаданные и обложки не сохраняются в профиле. В карточке слушателя есть «Копировать» и системное «Поделиться»; если меню отправки недоступно, Aura копирует название и исполнителя. [Протокол и ограничения](docs/architecture/media.md).

В рабочем режиме Smart Feed перебирает доступные эфиры принятых друзей и переходит к следующему после ошибки подключения, завершения эфира, паузы в 3 секунды или тишины в 12 секунд. Порог тишины — около −60 dBFS с гистерезисом. Если очередь пуста, текущий эфир остаётся активным при паузе; Smart Feed ждёт следующего обновления присутствия. Пока играет текущий эфир, Aura заранее запрашивает приглашение следующего друга. При переключении новый поток подключается и заполняет jitter-буфер, затем Aura выполняет плавный crossfade примерно за 200 мс; если подключение не удалось, текущий эфир продолжает играть.

## Интерфейс и управление

Приложение запускается в рабочем режиме. Переключатель демо и запуск деморежима через `--demo` убраны; статические сценарии `--render` оставлены для проверки интерфейса разработчиком.

- Повторное нажатие выбранного источника снимает его выбор. Захват начинается кнопкой «В эфир».
- Наведение на активные кнопки показывает подсказку через 550 мс, включая значки друзей и Smart Feed.
- Во вкладке «Друзья» кнопка «Очередь» открывает ручной порядок Smart Feed. Стрелки перемещают друзей, «Сохранить» запоминает порядок между запусками, «Отмена» и Escape оставляют прежний. Редактирование не останавливает эфир; звёзды и исключения сохраняют своё действие.
- Удаление друга требует подтверждения в отдельном окне. Отмена и Escape сохраняют контакт; подтверждение завершает активное соединение для отзыва доступа.
- Tab — следующий элемент, Enter/Space — активировать; ↑/↓ — громкость. В окне подтверждения сначала выбрана «Отмена».
- Windows-трей: открыть окно, эфир, Smart Feed, следующий друг, число слушателей и полный выход. Закрытие окна скрывает его в трей. При недоступном трее закрытие завершает приложение.

## Структура

```text
apps/desktop       Окно, события ОС, поверхность, трей
crates/aura-core   Состояние и команды автономного прототипа
crates/aura-ui     Представление на EvertyUI
crates/aura-audio  Process Loopback, Opus, jitter, WASAPI output
crates/aura-network Приглашения, авторизация, QUIC/TLS
crates/aura-mesh   Постоянный Aura ID, libp2p Noise, Circuit Relay
crates/aura-social Локальный профиль, друзья и взаимное согласие
crates/aura-media  Метаданные трека, обложки и ограниченный wire format
apps/node         Headless bootstrap/relay service для VPS
everty-ui          Локальные исходники UI toolkit
docs/architecture Границы модулей и дальнейшие этапы
```

Ядро не зависит от интерфейса, платформы и сетевого транспорта. Локальная папка `doc/` с исходным планом, каталоги `target/` и превью `artifacts/` исключены из Git. Корневой `Cargo.lock` фиксирует зависимости приложения.

## Проверка

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p aura-desktop -- --sources
# Явный аппаратный тест (не для CI):
cargo run -p aura-desktop -- --audio-smoke
cargo run -p aura-desktop -- --mesh-smoke
```

`--audio-smoke` запускает отдельный дочерний процесс с тихим синтетическим тоном, захватывает **только его**, передаёт Opus по loopback QUIC, декодирует и выводит через WASAPI с громкостью 0. Чужие приложения и микрофон не захватывает, аудиофайлы не создаёт. Проверяет число кадров и ненулевой декодированный сигнал, закрывает тестовые процессы/соединения.

`--mesh-smoke` проверяет запрос дружбы между двумя временными профилями, запрет доступа до подтверждения, присутствие, получение текущего приглашения, остановку эфира, уход из сети, восстановление присутствия и удаление друга через публичный VPS. Затем приглашение, полученное по Aura ID, используется для аппаратного аудиотракта со сквозным Noise и заглушённым выводом. Параллельно проверяются синтетические название/исполнитель/альбом, состояние, таймлайн, обложка и обновление трека/паузы отдельным каналом. Профиль пользователя не затрагивается. Нужна сеть; это ручной integration-тест, не CI. Дополнительный аргумент позволяет указать свой полный relay multiaddr; для рабочего UI тот же адрес задаётся через `AURA_RELAY`. Цикл дружбы и передача метаданных также проверяются автоматически через локальный relay без устройств и Интернета.

Автотесты проверяют Opus/PLC, jitter bounds/reordering, некорректные пакеты, неправильный токен/сертификат, защищённые QUIC/relay round trips и отзыв доступа. 2026-10-21 пользователь подтвердил воспроизведение между двумя ПК в LAN и через Интернет с ручным UDP-пробросом. Затем проверены 50/50 кадров и аппаратный аудиотракт через публичный VPS; после получения новых relay-сборок пользователь также подтвердил их работу. Длительные сессии, обрывы и смена сети ещё требуют испытаний. Автоматический NAT hole punching пока не реализован.

PNG-превью использует тот же путь рендеринга EvertyUI, что и окно, без запуска GUI:

```powershell
New-Item -ItemType Directory -Force artifacts
cargo run -p aura-desktop -- --render artifacts/playing.png playing
cargo run -p aura-desktop -- --render artifacts/settings.png settings 1.5
cargo run -p aura-desktop -- --render artifacts/live.png live
cargo run -p aura-desktop -- --render artifacts/live-capture.png live-capture 1.5
```

Сценарии: `idle`, `playing`, `settings`, `broadcast`, `waiting`, `live`, `live-capture`, `friends`, `friend-listening`, `friend-editor`, `friend-remove`, `friend-tooltip`, `queue`, `queue-page2`, `queue-empty`, `queue-error`, `media`. Последний аргумент — DPI-масштаб (0.5–4). Эти превью статические, без обращения к устройствам. Windows-сценарий `--render <file> media-source <scale> <PID>` читает реальные метаданные выбранного источника для визуальной проверки без захвата и передачи звука.

Ручная очередь Smart Feed готова. Работают два независимых узла: `aura.ltwo.ru` и `aura2.ltwo.ru`, параллельное присутствие, выбор доступного узла при старте и восстановление приватного эфира с прежним приглашением. Публичные эфиры подключены к нативному клиенту: выберите источник, переключите «По приглашению» на «Публично», задайте название и нажмите «В эфир». На вкладке «Эфиры» доступны общий каталог настроенных узлов, Play/Pause, раскрывающийся поиск, прокрутка и избранные авторы с сохранением между запусками. Оба VPS поддерживают серверную раздачу; внешний тест на основном узле доставил 10 слушателям по 50/50 кадров, на резервном — трём слушателям по 50/50. Пилот ограничен 32 слушателями на комнату и общими ресурсами узла. Публичный эфир автоматически восстанавливается на доступном настроенном узле: слушатели находят того же автора по прежней ссылке, если у них есть общий работающий узел. Повторные попытки ограничены 60 секундами после обнаружения обрыва; накопленные кадры не проигрываются. Межузловая репликация каталога пока не реализована. [Community Nodes](docs/architecture/community-nodes.md), [публичные эфиры](docs/architecture/public-broadcasts.md), [эксплуатация Aura Node](deploy/README.md).
